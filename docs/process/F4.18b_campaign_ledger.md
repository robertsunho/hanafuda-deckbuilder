## Why this campaign exists

Recon found **four** round-end pipelines, not two:
1A bank (`bankScore`), 1B natural / 1C forced-auto-bank (`_finalizeTurn`), and 1D
consumable-empty-hand (`_checkRoundEndOnEmptyHand`). The core teardown (field scoring → flow
decay → enhancements → log → hex hook → spirit hooks → phase) is **IDENTICAL** across 1A/1B,
but several spirit/economy tenants are duplicated inline (crow, decay, snails) with drifted
ordering, and **1D is a severely stripped pipeline that omits almost everything** — a real
gameplay bug (consumable-ended rounds skip flow decay, enhancements, logging, crow, decay,
snails, field scoring).

**Strategy (per recon verdict, DRIFTED / risk LOW):** migrate the duplicated inline tenants
into hooks FIRST. Once crow/decay/lincoln/napoleon live in `onRoundEnd`/`onBank`/
`onPushFailure` hooks, the inline blocks vanish and all paths route through the
already-identical `_fireSpiritHook` calls. THEN unify the four trigger paths into a single
`_endRound(trigger)` method — by which point it's a mechanical merge with almost no inline
code left. 1D folds in last, inheriting the full teardown (fixing the bug).

---

## Behavior-change policy

Each step is tagged:
- **[PRESERVE]** — pure refactor; behavior identical on all paths. Test asserts unchanged behavior.
- **[FIX]** — deliberate behavior change (almost always: a tenant now fires on the 1D path
  where it was previously omitted). Test asserts the NEW behavior; commit message + this
  ledger flag it explicitly as a fix, not a refactor.

Migrating a tenant into `onRoundEnd` is inherently **[FIX]** for the 1D path, because
`_fireSpiritHook('onRoundEnd')` already fires on 1D — so the migrated tenant starts firing
there. This is desired (1D's omissions are bugs). We surface it every time rather than
letting "migration" quietly smuggle in behavior changes.

## New hooks this campaign introduces

- `onBank({ spirit, run, roundManager })` — fires only on explicit bank (step 3, Lincoln).
- `onPushFailure({ spirit, run, roundManager })` — fires only on natural round-over with
  push penalty (step 4, Napoleon).
Both are bank/fail-specific by design and do NOT fire on all round-ends — they're added to
the spirit hook interface alongside `onRoundStart`/`onRoundEnd`. Document them in the
SpiritEffects.js header block when introduced.

## The target shape (step 6)

```js
_endRound(trigger) {
  // trigger: 'banked' | 'natural' | 'forced_auto_bank' | 'consumable_empty_hand'

  // ── Trigger-specific prologue ────────────────────────────────────────
  if (trigger === 'banked') {
    run.onBank(this);
    const hex = getActiveEffect();
    if (hex?.onBank) hex.onBank(run);
    this._fireSpiritHook('onBank');                 // engine_lincoln (step 3)
  }
  if (trigger === 'natural' && this._pushPenaltyActive && !this._dogProtection) {
    run.onPushFailure(this);
    this._fireSpiritHook('onPushFailure');          // engine_napoleon (step 4)
  }

  // ── Shared core teardown (runs for ALL triggers, including 1D) ────────
  this._trackSnailsUnplayed();                       // step 5 decision pending
  this._scoreFieldCards();
  run.applyFlowDecay();
  this._applyPostRoundEnhancements(this._capture.getAll());
  logger.logRoundEnd(...);
  this._roundEndingAfterDecision = false;
  const hex = getActiveEffect();
  if (hex?.onRoundEnd) hex.onRoundEnd(this);
  this._fireSpiritHook('onRoundEnd');                // crow + decay (steps 1,2) live here
  this._phase = 'round_over';

  return this._buildRoundEndResult(trigger);         // unified return, preserving consumed fields
}
```
Each of 1A/1B/1C/1D becomes a thin caller: compute its trigger, call `_endRound(trigger)`,
return the result. The bank path keeps its `yaku_decision` guard; 1D keeps its empty-hand
guard; etc. — only the teardown body unifies.
