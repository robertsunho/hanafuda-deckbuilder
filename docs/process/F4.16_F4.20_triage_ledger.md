# F4.16/F4.20 Triage Ledger — spirit-logic seepage bucketing

**Date:** 2026-06-04. **Author:** design conversation (Pass 2 over `F4.24_inventory_pass1.md`,
read against live source).
**Method:** Each site read in actual code, sorted by the three-part bucket-B test:
a site is **document-only (B)** ONLY if all three hold —
(1) it's a term in a formula a core system genuinely owns,
(2) lifting it would require inventing new indirection,
(3) the code reads clearer left in place.
Failing any one → **migrate (A)**. Default is A; B carries burden of proof.
A fourth bucket **(T)** = already owned by a separate scheduled task; not F4.16/F4.20 scope.

## Bucket counts (the sanity-check number)

- **A — Migrate to SpiritEffects hook:** 9
- **B — Document-only (formula term / structural):** 6
- **T — Has its own task already:** 4 (Past Life, Cuckoo Egg → F4.27; capstones → F4.x scoring; Northern Lion → shop)

B is 6 of the 19 substantive sites — at the threshold we agreed (~6). Within tolerance, but

exception. If you want B smaller, the only debatable one is `econ_recycling` (see notes).

## Bucket A — MIGRATE (self-contained, event-triggered; lift into a hook)

These fire on a discrete event (capture / discard / round boundary) and do a bounded thing
through the public RunManager API. They are the real F4.20 work. Precedent already exists:
`util_festival`, `econ_replica`, `econ_collector` are exactly this shape and already migrated.

| Spirit | Current home | Event | Migrates to | Notes / risk |
|---|---|---|---|---|
| `util_glory` | GRM `_addCapture` post-capture | bright captured | `onCaptureComplete` (new hook) | Bounded: draw N. Needs a post-capture spirit hook — see "new hook" below. Low risk. |
| `econ_recycling` | GRM `_handleFieldDiscard` | field-full discard | `onFieldDiscard` (new hook) | `+5*stacks` ki. `_handleFieldDiscard` is already a clean dispatch point; this becomes a hook fired there. Low risk. **Debatable B/A — see notes.** |
| `game_catcher` | GRM `_handleFieldDiscard` | field-full discard | `onFieldDiscard` (new hook) + return value | Routes card to hand instead of discard. Slightly trickier: it *intercepts* (changes return), not just side-effects. Medium risk — hook needs to signal "consumed". |
| `econ_reward` | GRM (push-success path) | push succeeds | `onPushSuccess` (spirit hook) | `+10%*stacks` of current ki. Hexagrams already have `onPushSuccess`; add spirit-side equivalent. Low risk. |
| `sym_crow` | GRM bank + natural-end (DUP) | round end | `onRoundEnd` | Already-correct hook exists for other spirits; Crow just never got migrated. **Also fixes the bank-vs-finalizeTurn duplication (Obs S8).** Low risk, high value. |
| `sym_osprey` | GRM `startRound` reset + deck-flip path | round start / deck flip | `onRoundStart` (reset) + deck-flip hook | Reset half is trivial (`onRoundStart`). The "first N flips to hand" half needs a deck-flip interception hook. Medium risk. |
| `sym_ants` | GRM `playHandCards` | card played | `onCardPlayed` (new hook) | `incrementPerElement(totalPlayed)`. Pure counter increment. Low risk. |
| `engine_ship` | GRM `_handleFieldDiscard` + ConsumableEffects Horse | discard | `onFieldDiscard` (new hook) | Counter increment on discard. Migrating de-dupes the two discard sites (Obs S8). Low risk. |
| `engine_moths` | GRM `_addFlippedCardToField` | wood slot created | `onWoodSlotCreated` (new hook) | Counter. Niche event but bounded. Low-medium risk (event is specific). |

**New hooks this bucket implies** (to add to the spirit hook interface + dispatch in GRM):
- `onCaptureComplete({ cards, run })` — fires once after a capture resolves (Glory; later Symbiosis).
- `onFieldDiscard({ card, run })` → may return `{ consumed: true }` — fires inside `_handleFieldDiscard` (Recycling, Catcher, Ship). **This single hook consolidates the discard seepage AND the F4.17 discard-pipeline concern — worth coordinating.**
- `onPushSuccess({ run })` — spirit-side mirror of the existing hexagram hook (Reward).
- `onCardPlayed({ cards, run })` — fires in `playHandCards` (Ants).
- deck-flip hooks (Osprey) — defer; see note.

**UPDATE (F4.17):** `game_catcher` was resolved as a GATE (`_tryCatcherIntercept` in GRM, runs
before the discard hooks), NOT an `onFieldDiscard` hook. The `{}` in SpiritEffects is the
intended end state — a gate isn't a declarative effect. The triage's "`onFieldDiscard` +
`{consumed}` return" plan (above, and the `game_catcher` Bucket A row) was reconsidered and
rejected during F4.17 (YAGNI until a 2nd interceptor exists). So of the original 9:
Glory/Recycling/Ship/Crow migrated to hooks; Catcher resolved as a gate.

**Sequencing caution:** several of these touch `_handleFieldDiscard`, which is *also* F4.17's
target. Recommend Glory + Crow + Reward + Ants FIRST (clean, independent), then the
discard-hook cluster (Recycling/Catcher/Ship) as a coordinated sub-task that doubles as F4.17
groundwork. Osprey deck-flip and Moths last (most specific events).

Each of 1-5 is independently shippable + verifiable. 6 is a single no-risk comment sweep.

explicitly deferred to their own tasks/waves.

## F4.20-FIX — Negative accumulators accrue post-transcendence [FIX] (2026-06-06)

migrations faithfully carried a pre-existing bug: discrete-event increment sites excluded
