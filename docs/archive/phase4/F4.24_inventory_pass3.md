## State-model raw notes (fresh capture for F4.24b)

**RunManager (persistent singleton) vs GameRoundManager (per-round orchestrator).**
- *RunManager persists across rounds* (constructor / `reset()`): `_ki`, `_allSpirits[]` (unified
  regulars+negatives; `spirits`/`negativeSpirits` are filtered getters), `_legendarySpirits[]` (currently
  unoccupied), `_consumables[]`, `_round`, `_act`, `_totalScore`, `_flow`, `_styleBase`, `_deck` (deep copy
  of ALL_CARDS, survives rounds, mutated by Three Marks), hexagram + blessing state. Owns the **economy
  formulas** (`getEffectiveCost`, `calculateKiReward`, `interestRate`, flow decay, push curve) and all
  spirit-roster mutation/acquisition.
- *GameRoundManager resets every round*, via two methods + `startRound`: `_resetRoundState()`
  (`GRM:248-274`, plain round-local fields — `_phase`='idle', `_yakuBeforeTurn`, push counters
  `_pushCount`/`_pushDepth`/`_pushPenaltyActive`/`_pushPenaltyWaived`, `_bullseyeInventory`, zodiac flags,
  etc.) and `_resetScoringState()` (`GRM:284-292`, runs **after** `onRoundStart` to honor a timing
  contract — `_runningScore`, `_cumulativePoints` (capstone_nature carry), `_scoringEvents`, `_spentCardIds`).
  `startRound()` (`GRM:326-388`) resets the deck/hand/field/style, fires per-round symbiont resets +
  `onRoundStart`, then deals. **GRM reads spirits live** from `run.activeSpirits`/`scoringSpirits`/
  `allSpirits` — no `_spirits` snapshot.

**Per-element accumulator model.** Accumulator spirits carry `spirit.elements[]` — one element object per
stack (vs `spirit.state` for stateful non-accumulators; vs nothing for plain spirits). Each element holds
its counters + an `acquiredRound` tag (for Cat-5 maturation). Seeded by `_freshAccumulatorElement(spiritId)`
(`RM:620`): `{ ...ACCUMULATOR_INIT[id](), acquiredRound: this._round }` (empty `{}` if no init fn).
`ACCUMULATOR_INIT` (`RM:51`) maps each id → a fresh-state factory; `ACCUMULATOR_SPIRIT_IDS` (Set, `:34`)
gates accumulator-vs-state branching. Stacking appends one element (`_addAccumulatorElement` `:626`). Read
via the aggregate helpers (Part 4). (DP-03 routed this mechanism to RunManager.)

**Snapshot / transcendence model.** Negatives carry `powerLevel` (not stackCount); `effectivePower` returns
`powerLevel` for them. `_buildTranscendedNegative(spirit, powerLevel)` (`RM:670`) is the single source of
negative construction (both natural cascade-at-4 and Amber call it); it bakes power onto the object and
folds `.elements` into one `state` via `_aggregateElementsForNegative` (`RM:649`) → the per-spirit
`NEGATIVE_SNAPSHOT` fn (`SpiritEffects.js:303`; `snapshotCat1Linear/Dual/Exponential` + seen-array + Cat-5
maturation variants). F4.26 Option B (lossless): transcend snapshots `stackCount` (all 4 contribute) and
replaces the spirit **in place** at its chain index (`splice(idx,1,…)` `RM:879`), preserving placement.
`_freshNegativeState(spiritId, powerLevel)` (`RM:640`) builds a non-compounding zero-state negative for
Past Life copies / negative Cuckoo hatches (same shape, counters at zero). `snapshotPower` is a local var
in `_acquireSpiritStack` (`RM:873`), not a helper.
